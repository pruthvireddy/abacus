# Phase 3 acceptance and evidence checklist

This is a review checklist for the experimental [protocol](protocol.md), not a
record that every item passed. Actual executions and limitations belong in
Phase 3's verification record. Local specification-model tests, source-byte
checks, native Pine compilation, Replay observations and scientific validity
are separate evidence layers.

  tests and verification remain unchanged. The Phase 2 protocol, sources,
  inventory, cases and findings remain unchanged.
- Protocol 3.0.0, settings, input declaration and decisions precede detector

- The initial independent audit found all **33** declared source pins matching.

## Calculation and local-model review

| Area | Acceptance evidence |
|---|---|
| Distribution integrity | Empty/all-zero, invalid/negative/nonfinite mass, overflow, absent required bars, no stale state after reset, raw/normalized mass conservation and identified row bounds |
| Profile lineage | Contract/feed/adjustment/tick, zero grid, allocation method, exact reference sessions and last completed bar, coverage/volume/overflow/readiness, code/settings/input identities |
| N1 plateau and prominence | Hand-worked flat, single, equal plateau, broad shoulder, two distributions, unequal peaks, shallow trough and endpoint fixtures; complete plateaus, deterministic lowest row, literal inclusive thresholds and first-higher searches |
| N1 qualification and regions | Ranked separation/rejection reasons, half-prominence contiguous bounds, integrated mass, stable row-based IDs, all overlaps retained and endpoint truncation flagged |
| LVN | Adjacent disjoint parents only, lowest intervening plateau with low-price tie, inclusive quarter-smaller-peak threshold, parent IDs, intervals, rejections and no endpoint invention |
| E1 | Two-row parent requirement, observed outside neighbor, inside/outside evidence, inclusive 0.10 contrast, shared grid boundary and half-row uncertainty, side-specific truncation; no centers/VA boundaries relabeled |
| Caps | Uncapped qualification ledger retained; deterministic 8/7/16 presentation caps, omitted IDs/counts, and no pivot/target semantics |
| Composite | Three expected completed RTH members; input-order invariance, explicit lineage/mass, duplicates, gaps, partial members, contracts, feeds, grids, measurements and adjustment mismatches rejected |
| P1/P2 | Separate formulas and identities; exact and interval arithmetic, outward tick rounding plus raw results, invalid bounds/contracts, missing anchors, unsupported/later confirmation, and known opposite-bound identity |
| Snapshot | Exact cutoff and final bar, frozen copied prices/profile/anchor IDs, later mutation cannot alter saved map, reset/restart fixtures, no incomplete-period substitution |
| Baseline | Same original 19 values under equivalent synthetic inputs; source-preservation/parity guard is distinguished from actual Pine execution |

Tests should assert hand-worked values and invariants, not only mirror branches
or search for source strings. A Python translation passing does not establish
that Pine compiles or executes the same algorithm. A static baseline text guard
helps identify changes; native 19-field parity still requires actual Replay.

## Training and comparison acceptance

- Save and hash all seven additional actual expanded maps before reading any of
  their answers. Explicit per-date failures are honest deliverables but do not
  permit target reveal or establish successful map generation.
- No manual first-pass anchor is selected after answer reveal. Unsupported
  anchors remain unavailable; retrospective illustrations remain separate.
- Source observations retain revisions, conflicts, compound labels, uncertainty,
  source class and timing. Execution arrows never become selection labels.
- Apply the frozen [comparison contract](comparison-specification.md): global
  tolerance, family/window eligibility, one-to-one assignment, preserved ambiguity,
  unmatched sources/generated candidates and presentation-cap omissions.
- No candidate coverage statistic is reported when actual expanded maps are
  missing. Zero eligible references is not zero-percent coverage.
- Profile fidelity problems remain separate from segmentation misses. No
  parameter retuning, automatic anchor/balance discovery, LIS/pivot selection,
  ordered bullish/bearish targets, profitability test, publication or deployment.

## Delivery and readiness decision

Deliver the derivative, frozen inputs, specifications, actual check records,
ten candidate records or explicit failures, comparison status, installation and
Replay instructions, and Phase 4 handoff. The handoff must state which interfaces
are implemented and which native/data/source gates remain unresolved. An
engineering implementation with passing local tests can still be **not ready
for empirical selection research** if native expanded maps and training
comparisons are unavailable. Do not seal incomplete evidence as a completed run.
